# Issue triage

Move a GitHub issue to a defensible state, category, and **accountable role**.

Triage is not a reading-comprehension exercise on the issue body. It is a
comparison between what the issue claims and what is true right now. Both
halves — state and route — turn on evidence gathered outside the issue text.

## Hard constraints

**No label vocabulary lives in this skill.** State and category come from the
repo's own `docs/agents/triage-labels.md`; route values come from GlassFrog via
`devops-excellence/templates/role-labels.json`. Every previous copy of the
vocabulary in this org has gone stale — see `reference/UPSTREAM.md`. If you find
yourself about to write a label name into this file, don't.

**Never triage from the issue body alone.** A measured pass over a 54-issue
backlog found roughly 40% of issues had drifted from their own text — already
resolved, reversed, reduced in scope, or decomposed by ADRs that landed after
filing. State assigned without a ground-truth pass is a guess with a label on it.

**Exactly one state role and one category role per issue.** Conflicts are
surfaced to the human, never resolved silently.

**Never touch a lock label.** `status:in-progress` and equivalents belong to the
dispatch claim protocol, not to triage. Setting one reserves work you are not
doing; clearing one unlocks a session that is.

**Claim by label, never by assignment.** Several IP repos run automations that
trigger on `issues: [assigned]`, so assigning to claim spawns a session — the
claim step becomes the runaway it was meant to prevent.

**Every comment opens with the AI disclaimer**, on its own line:

```
> *This was generated by AI during triage.*
```

## Algorithm

### 1. Resolve the vocabulary

Read `reference/vocabulary-discovery.md` and follow it. Two sources with
different scopes: the repo's `docs/agents/triage-labels.md` for states,
categories, and enrichment axes; `role-labels.json` for the legal route values.
Confirm against `gh label list` what actually exists in this repo — the docs
describe intent, the label list describes reality.

If the repo has no `docs/agents/triage-labels.md`, fall back to the canonical
roles and **say so in the comment**. A silent fallback installs a vocabulary
nobody chose.

### 2. Ground-truth the issue

Read the issue in full — body, every comment, labels, reporter, dates. Parse any
prior triage notes so you do not re-ask a question already answered.

Then check it against live state:

- Has the work already landed? Search `main` for the thing it asks for.
- Has an ADR since resolved, reversed, or reduced it?
- Do cross-referenced issues or open PRs supersede it?
- For a bug: attempt reproduction. A confirmed repro is the strongest input to an
  agent brief; a failed one is a strong signal for the awaiting-information state.
- Read `.out-of-scope/*.md` if present and surface any prior rejection that
  resembles this issue — matched by concept, not keyword.

**Record the date you checked.** "Verified against `main`" is unfalsifiable;
"verified 2026-08-02" tells the next reader when to re-check.

If the issue has drifted, state the drift in the comment **before** assigning a
state. The drift is usually more useful than the state.

### 3. Classify

One category role, one state role, from the vocabulary resolved in step 1.
Recommend with reasoning. If a state role already present conflicts with your
recommendation, or the transition looks unusual, flag it and ask before acting.

### 4. Infer the route

Read `reference/route-inference.md` and follow it. Pull the role corpus in one
`glassfrog_list_roles` call, join to the manifest on `original_role_id ?? id`,
and weigh domains, then accountabilities, then purpose.

Routing runs in **every** IP repo, including those whose `triage-labels.md` does
not mention the axis — SAE-009 put route authority in GlassFrog, not in any
repo's doc.

Then take exactly one branch, per that reference:

- **Apply** — one role is clearly accountable. Create the label lazily from the
  manifest's exact `name`/`color`/`description`, apply it, remove any other route
  label, and quote the evidence in the comment.
- **Escalate** — ownership is genuinely unclear. Apply `needs-triage-decision`,
  apply **no** route label, and comment naming each candidate with the
  accountability or domain text its claim rests on.
- **Degrade** — GlassFrog is unreachable. Skip routing, say so with the date, and
  do **not** fall back to matching on role names.

### 5. Apply enrichment

`priority:*`, `area:*`, and any repo-local axis. These add signal; they never
replace a state.

### 6. Write

Post one comment carrying the whole reasoning — drift found, state and why,
route and the evidence it rests on, roles named but not labelled. Then apply the
labels. One comment, not several.

### 7. Hand off (only when asked)

When the issue lands in the agent-ready state — whatever this repo calls it, per
step 1 — write an agent brief following `reference/AGENT-BRIEF.md`: behavioral,
not procedural; no file paths or line numbers, because the issue may sit in the
queue for weeks.

If the issue is also being dispatched, **invoke the `writing-dispatch-prompts`
skill** for the prompt contract. Do not restate that contract here; it is a
sibling skill in this plugin and owns the seven parts, the two-signal claim
check, and the claim-by-label rule.

When an *enhancement* is rejected outright — never a bug — record it per
`reference/OUT-OF-SCOPE.md`: one file per concept, never per issue.

## Reference files

- `reference/vocabulary-discovery.md` — the two vocabulary sources, their
  scopes, known per-repo divergence, and lazy label provisioning.
- `reference/route-inference.md` — the GlassFrog join, the evidence hierarchy,
  the confidence gate, and the three branches.
- `reference/AGENT-BRIEF.md` — writing a durable agent-ready handoff.
  Verbatim from Matt Pocock's `triage` skill (MIT).
- `reference/OUT-OF-SCOPE.md` — the concept-keyed rejection knowledge base.
  Verbatim from the same source (MIT).
- `reference/UPSTREAM.md` — provenance and digests for the two vendored files,
  and why the upstream `SKILL.md` was deliberately not copied.

## Promote to `tested` when

This skill has produced a defensible route on at least two issues in at least
two different repos — one apply, one escalate — with the escalation comment
naming candidates by quoted accountability text, and with the degradation branch
exercised once against an unreachable GlassFrog.
